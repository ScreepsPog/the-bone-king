# Base feel: an army that stays close, enemies that charge, walls (2026-11-12 02:00 PST to 02:32 PST)

- "I definitely like the angled cam the best."
- "I also want the friendly skeletons/army to stay near the player, not roam on their own... They should not attack/go

- "Add some obstacles to the current map... The current bolt should not go through walls, and AI should navigate

## What the agents did

Claude Code (Claude Fable 5.2) proposed an order, the director approved it, and Claude built this round.

**The order agreed** (the director chose "next round" for the bone spear):

| When | What |
|---|---|
| This round | Army roaming, enemies charging the wizard, walls with pathing, sharp text, Angled camera locked in. |
| Next round | Bone spear, built with one tough enemy so "weak against tough enemies" can be judged. |

**Built** (commit `d4951bc`, 02:22 PST):

- **Army.** Each skeleton idles at its own spot inside a 350-unit circle around the wizard and strolls to a new spot
  every 1.5 to 4.5 seconds. Its speed eases with distance, from a stroll (120) to a run (800) when the wizard runs
  ahead. It attacks only an enemy within 300 units of itself and within 500 units of the wizard. When a fight ends
  it idles where it stands.
- **Enemies.** They head for the wizard and turn on a skeleton only when it is within 90 units and in front of them.
  Each one bends its approach by up to 35 degrees to its own side and has its own speed (plus or minus 12%), so a
  wave arcs in and surrounds.
- **Walls.** Ten boxes around the start: a long wall, a wall across, a corner, a gate with a 200-unit gap, four
  pillars. They stop the wizard (collision), every unit and the Bolt (simulation). A flow field, a 64 by 64 grid
  that stores "which way to the wizard" for every square, leads units around them. It is rebuilt only when the
  wizard steps into another square, and a unit reads it only when a wall blocks its straight line.
- **Text.** The HUD drew small bitmap fonts stretched up, which is why it was blurry. It now draws the Roboto outline
  font at exactly the size shown, and the layout scales with the screen (1.0 at 1920x1080, 2.0 at 4K, never below 0.5).
- **For testing.** `Wiz.Tune <Name> [Value]` changes any crowd number while playing, `Wiz.Obstacles` switches the
  walls, and the debug overlay draws the roam circle (green) and the leash (yellow).
- The debug keys (1, 2, 3, H) no longer exist in the shipped build.

Tests were written first: 14 new ones, 11 of which failed against the old behavior before any new code was written
(the other three guard behavior that already held). 36 tests pass now, plus three key-press scenarios; one of them
walks the wizard into a wall and checks he stops.

## What failed and the fix

- **The first sharp-text version drew no text at all.** The build and all tests passed; the screenshot showed an
  empty HUD. The engine skips canvas text whose font has no font asset behind it, silently. Fix: use the engine's
  Roboto font asset. Found only because a screenshot was looked at, not because anything reported an error.
- **One old test broke for a good reason.** It assumed every grunt walks at exactly the same speed. Enemies now have
  their own speeds, so the test switches the variation off to measure what it was written to measure.
- **A long shell command with an apostrophe in a comment failed to parse** (the same class of failure as yesterday).
  Edits now go through a script file.

## Web package

Development build for the web, packaged at 02:23 PST, `BUILD SUCCESSFUL`.

- Size: 290.9 MB staged, largest file the `.wasm` at 192.0 MB (Development; Shipping is the one that ships).
- Browser check, forward tier: ready in 2.8 s. The walls, the wizard, grunts, the two circles and the new text draw.
- **A second cause of the blurry text was found here.** The page rendered at 1024x768 on a display scaled to 150%,
  and the browser stretched the picture. The engine setting `MaxDevicePixelRatio` was 1; it is now 2, so the page
  renders at the display's real pixels (1536x1152 in the same window). For this check the setting was changed in the
  staged page by hand; the next package applies it from the project settings. It costs more pixels to draw, so frame
  rate at 4K full screen has to be watched.
- 640x480: checked with the browser pane's size emulation. The layout fits and nothing overlaps. The emulation acts
  as a touch phone (2 pixels per point, on-screen sticks), so a real 640x480 desktop window is covered by the layout
  test, not by eye.
- Not checked by the agents: frame rate (the pane was hidden, which throttles the page, so its 12 to 18 fps reading
  means nothing), WASD and mouse aim in the browser, and the feel of the army and the pathing. A computer-use
  playtest in Brave was approved by the director for 03:00 PST.
