How it is built:

- The whole crowd is plain data in one simulation, stepped once a frame by one manager. No unit is an actor. This is
  what keeps a browser build fast and lets the rules be unit-tested without starting the game.
- Everything on screen is an engine basic shape tinted by code. No content assets were made.
- 22 automated tests, one key-press scenario and one screenshot scenario cover it.

## What failed and the fix

- **The wizard could not move.** The simulation tests, the build and the first web package all passed, but a
  scenario that presses W for one second showed the wizard still at the start. The key reached the game and the move
  handler ran; the velocity stayed zero. Cause: the capsule sat exactly on the floor while movement was locked to a
  flat plane, so the engine could not push it up out of the floor and blocked every move. Fix: stand the capsule 2
  units above the ground. The scenario failed before the fix and passes after (578 units in one second).
- **New folders were not found by the compiler.** Includes like `Sim/CrowdSim.h` did not resolve until the module
  folder was added to the include paths.
- **A build said "Succeeded" without compiling a new file.** Building again picked it up. Now the log is checked for
  the file's name after adding one.
- **One long write command failed to parse** and wrote nothing; the files were written one at a time instead.
- **Browser automation could not type into the game.** Keys sent by the agent's browser tool did not reach the
  canvas, so input in the browser is on the director's test list, and the keys 1, 2, 3 and H were added so the
  cameras can be compared without a console.
